# 02. 기능 · API 명세

이 문서의 내용은 고정이다. 바꿀 때는 먼저 이 문서를 고친다.

## 1. Meeting 모델

필드 8개. 이 순서, 이 타입 그대로 둔다.

| # | 필드 | 타입 | 필수 | 설명 |
|---|---|---|---|---|
| 1 | `id` | INTEGER, PK, AUTOINCREMENT | - | 회의록 번호 |
| 2 | `title` | VARCHAR(200) | 필수 | 회의 제목 |
| 3 | `met_at` | DATETIME (UTC) | 필수 | 회의를 한 시각 |
| 4 | `attendees` | TEXT | | 참석자. 쉼표로 구분 |
| 5 | `body` | TEXT | 필수 | 받아쓴 원문 또는 붙여넣은 메모 |
| 6 | `summary` | TEXT | | 요약 |
| 7 | `decisions` | TEXT | | 결정사항 |
| 8 | `todos` | TEXT | | 할 일 |

- **AUTOINCREMENT 를 테이블에 실제로 넣는다.** SQLite 는 PK 만 주면 지운 id 를 다시 쓴다.
  SQLAlchemy 면 `__table_args__ = {"sqlite_autoincrement": True}` 를 준다
- `summary` · `decisions` · `todos` 세 갈래 결과는 각각 **줄바꿈으로 구분**해 저장한다
- `todos` 는 한 줄에 하나씩, `내용 | 담당자 | 기한` 형식으로 저장한다

## 2. 세 갈래 구분 기준

아래 기준을 **이대로 프롬프트에 넣는다.**

```
요약 - 회의 전체를 3~5줄로. 새로운 사실을 지어내지 말 것
결정사항 - 「하기로 했다 / 확정 / 승인」 처럼 합의가 끝난 것만. 논의만 하고 안 정한 것은 넣지 말 것
할 일 - 담당자와 기한이 드러난 것만. 담당자가 없으면 미정으로 적을 것
셋 중 어디에도 안 들어가는 잡담은 버릴 것
```

## 3. 검증

| 상황 | 응답 |
|---|---|
| `title` / `met_at` / `body` 가 없음 | 400 |
| 없는 id | 404 |
| 스펙 외 필드가 들어옴 | 422 |
| 업로드 파일이 mp3, wav 가 아님 | 415 |
| 업로드 파일이 25MB 초과 | 413 |

- FastAPI 기본은 422 다. **검증 실패를 400 으로 바꾸는 예외 핸들러를 둔다.** 스펙 외 필드만 422 로 남긴다
- 스펙 외 필드를 걸러내려면 Pydantic 모델에 `extra="forbid"` 를 준다.
  기본값으로 두면 모르는 필드가 조용히 무시되어 201 이 나온다

### 시각 (UTC)

- `met_at` 은 UTC 로 저장한다
- 화면의 `datetime-local` 값은 로컬 시각이다. **보낼 때 UTC 로 바꾸고, 받아서 표시할 때 로컬로 되돌린다**

## 4. REST API

7개. 경로는 `/api/` 접두사 필수.

| # | 메서드 | 경로 | 성공 | 설명 |
|---|---|---|---|---|
| 1 | POST | `/api/notes` | 201 | 저장하며 세 갈래 구분까지 |
| 2 | GET | `/api/notes` | 200 | 목록. `q` 로 제목 · 참석자 검색, `from` · `to` 로 날짜 |
| 3 | GET | `/api/notes/{id}` | 200 | 단건 |
| 4 | PUT | `/api/notes/{id}` | 200 | 수정 |
| 5 | DELETE | `/api/notes/{id}` | 204 | 삭제 |
| 6 | GET | `/api/todos` | 200 | 할 일만 모아 보기 |
| 7 | POST | `/api/upload` | 200 | 녹취 파일을 받아 본문 텍스트로 반환 |

- 목록(`GET /api/notes`)에는 `body` 를 뺀다. 단건(`GET /api/notes/{id}`)에는 넣는다
- `GET /api/todos`
  - 응답 필드: `what` / `who` / `when` / `note_id` / `note_title`
  - 회의 날짜(`met_at`) 오래된 순으로 정렬한다

## 5. 검색 규칙

- `q` 는 **제목과 참석자**에 대한 부분 일치. 본문은 검색하지 않는다
- `from`, `to` 는 `YYYY-MM-DD` 이고 양끝을 포함한다. `to` 는 그날 23:59:59 까지
- `from` · `to` 는 **화면의 로컬 날짜 기준**이다

## 6. 할 일의 기한

- 기한은 회의에서 말한 그대로 둔다 (「다음 주 금요일」 같은 자유 문구)
- 날짜로 바꾸지 않는다
- 기한으로 정렬하거나 거르는 기능은 만들지 않는다

## 7. 실패 처리

| 상황 | 처리 |
|---|---|
| 받아쓰기나 구분이 실패 | 저장은 그대로 201. `summary` · `decisions` · `todos` 를 빈 값으로 둔다. 화면에는 **구분 실패**로 표시하고, 서버는 `logging` 으로만 남긴다 |
| 본문이 회의 내용이 아님 | 세 칸을 빈 값으로 둔다 |
| 본문이 20자 미만 | 구분을 부르지 않고 세 칸을 빈 값으로 둔다 |
| `POST /api/upload` 가 외부 호출에서 실패 | 502 |
| Gemini 가 429 · 503 | 잠시 뒤 1번 다시 부른다 |
