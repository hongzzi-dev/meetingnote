## 화면

목록 · 넣기 · 상세 · 할 일, 4종이다.

- 배치와 요소 이름은 `docs/화면구성.pdf` 를 따른다
- 요소 id 는 그 파일에 적힌 그대로 쓴다

## 디자인

- UI 는 macOS 스타일로 한다
- CSS 라이브러리는 Tailwind 를 써서 깔끔하고 모던하게 만든다

## 왜 이렇게 나누는가 - 관심사 분리

한 문서는 한 가지 질문에만 답한다.

| 질문 | 문서 |
|---|---|
| 무엇을 왜 만드는가 | `01-product.md` |
| 어떻게 동작해야 하는가 | `02-specs.md` |
| 어떻게 보여야 하는가 | `03-design.md` |
| 무엇을 어떤 순서로 하는가 | `04-tasks.md` |
| 어떤 방식으로 짜는가 | `05-conventions.md` |

- **바뀌는 이유가 다르면 문서도 다르다.** 화면 배치가 바뀌어도 API 명세는 그대로이고, 기능이 늘어도 코딩 규칙은 그대로다. 한 곳만 고치면 된다
- **중복이 없다.** 같은 내용이 두 곳에 있으면 한쪽만 고쳐져 어긋난다. 각 내용은 맡은 문서 한 곳에만 둔다
- **필요한 것만 읽는다.** 화면을 고칠 때는 `03-design.md`, API 를 고칠 때는 `02-specs.md` 를 보면 된다
- **코드 구조와 맞물린다.** 백엔드(`backend/`)는 `02-specs.md`, 프론트(`frontend/`)는 `03-design.md` 와 짝을 이뤄, 문서의 경계가 코드의 경계와 같다
